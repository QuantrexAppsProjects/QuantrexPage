    Our method

    The QuanTrex
    Method.

    Request the playbook Engagement models Book a scoping call

    Abstract

    We present a delivery method for small, senior software teams that trades heroics for measurement. Each feature is specified in plain language, translated into a user story, an interface contract and an automated test, then built in a two-week cycle that ends with a live demo. Quality gates for performance, accessibility and security run on every change. The result is software that matches its brief and a client who knows where the project stands on any given day.

    Procedure

    1. DiscoverInterviews, data review and a one-page problem statement everyone signs.
    2. SpecifyStories, API contracts, acceptance tests and a priced backlog.
    3. DesignFlows and a clickable prototype, tested with five real users.
    4. BuildTwo-week sprints, a demo every Friday, CI quality gates on every PR.
    5. LaunchStaged rollout, monitoring, store submission and handover docs.
    6. ImproveAnalytics review, a prioritised next release, support with SLAs.

    Field notes

    From the
    build log.

    Engineering5 min

    Spec-driven development in the age of coding agents

    AI writes code quickly. It still needs to be told what correct looks like.

    Read

    Coding assistants are now part of most teams' daily workflow, and they are very good at producing plausible code. Plausible is not the same as correct. The fix is old-fashioned: write the specification first. When every feature starts as a user story, an interface contract and a failing test, an agent has a target it can be checked against, and a reviewer has something concrete to approve. We've found the spec also becomes the best documentation a project has, because it's the one artefact that's always current.

    Security4 min

    Passkeys: the cheapest conversion boost you'll ship this year

    Fewer forgotten passwords, fewer support tickets, and phishing gets much harder.

    Read

    Passkeys replace passwords with a key pair stored on the user's device and unlocked with a fingerprint, face or PIN. They're supported across the major platforms and browsers, so most of your users can already use them. Because the private key never leaves the device and is bound to your domain, a fake login page can't capture it. Our advice is to offer passkeys alongside existing sign-in, prompt for one right after a successful login, and measure how many support tickets about access disappear.

    Performance6 min

    INP is the Core Web Vital most sites quietly fail

    Interaction to Next Paint measures how quickly your page responds every time someone taps.

    Read

    Google replaced First Input Delay with Interaction to Next Paint as a Core Web Vital in March 2024. Unlike FID, INP looks at responsiveness across the whole visit, so heavy JavaScript that runs after the first click now counts against you. A good score is 200 milliseconds or less at the 75th percentile. The usual culprits are long tasks on the main thread, oversized hydration and third-party scripts. Breaking work into smaller chunks and deferring what the user can't see yet fixes most of it.
